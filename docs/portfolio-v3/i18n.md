# Internacionalización (es/en/de/fr/it)

## Modelo

| Tema | Regla |
| --- | --- |
| Almacén | `localStorage`, clave `language`. Sin detección del idioma del navegador |
| Primer pintado | Siempre español (también el snapshot del servidor); el idioma guardado se aplica justo tras la hidratación |
| `<html lang>` | Sigue al idioma (`LanguageContext`) |
| Metadatos y JSON-LD | Siempre en español |

## Dónde vive el texto

| Contenido | Ubicación |
| --- | --- |
| Cadenas de UI | `src/data/translations.ts`, tipado a partir del bloque `es`; cada clave debe existir en los cinco idiomas |
| Textos largos | `src/data/content/{projects,diagrams}.i18n.ts`, `src/data/content/cases/*.i18n.ts` (`Record<Language, Copy>`) y `src/data/content/technical/dashboard.i18n.ts` |
| Fuentes en español | `src/data/projects.ts` y `src/data/diagrams.ts`: deben seguir sin imports (los scripts los cargan en solitario) |

## Páginas de caso

`page.tsx` fino de servidor (metadatos en español) + `*Content.tsx` de cliente con `useLanguage()`. Los fragmentos alrededor de `<code>`, `<strong>` y `<mark>` permiten que cada idioma reordene las palabras.

## Errores

Las Server Actions y la autenticación devuelven códigos estables que el cliente traduce (`t.auth.failures`); `/api/contact` añade un campo `code`.

## Disciplina

- `translations.ts` tiene exactamente 5 claves `errors:` y 5 `submit:` (lo comprueba `t04-sections-check`): las claves nuevas deben usar otros nombres.
- Las traducciones se escribieron sin revisión de hablante nativo (decisión del propietario).
- Descartado: cargar bajo demanda los diccionarios no españoles (ver [`rendimiento.md`](rendimiento.md)).
